## 技术领域

本发明涉及医疗数据安全、隐私计算与区块链技术领域，具体涉及一种基于零知识证明（Zero-Knowledge Proof, ZKP）的隐私原语执行可验证方法、基于区块链锚定的处理凭证与血缘链方法，以及相应的系统与计算机可读存储介质。

## 背景技术

医疗数据在诊疗、科研、公共卫生等场景间高频流转，跨系统全链路合规审计是监管的刚需。现有方案（如本系列专利 4 所述）将隐私处理元数据（masking_metadata、dp_metadata 等）嵌入 Arrow Schema 随数据流转，实现了"可读"的审计，但仍存在以下缺陷：

1. **元数据可读不可证**：下游读取的"已脱敏"声明无法被密码学验证，恶意或缺陷节点可伪造元数据宣称已处理，而实际输出残留明文；元数据与数据同源产出，缺失独立的验证通道。
2. **明文参与验证的悖论**：若以原始数据参与校验（重算脱敏结果比对），则验证过程本身暴露明文，与隐私保护目标直接矛盾；完全不经校验又无法发现"宣称已处理、实际未处理"的缺陷。
3. **跨系统链路取证成本高**：监管方需接触每个节点的内部日志才能确认处理发生，跨机构协作难、取证慢，无法支撑"零信任"合规核查。
4. **分级结果不可验证**：业务系统宣称"字段为 L3"，监管方无法确认等级由既定规则正确计算得出；规则是否被私自放宽也无从比对。
5. **门禁动作无证据**：最高敏感档（L4/L5）数据的整段替换动作缺乏可验证证据，无法证明"确已替换而非部分残留"，也无法证明替换时输入等级确实达到最高敏档。

## 发明内容

### 一、要解决的技术问题

本发明旨在解决：（1）处理声明"可读不可证"问题；（2）验证过程暴露明文的问题；（3）跨系统全链路合规取证的零信任问题；（4）分级结果正确性验证问题；（5）最高敏门禁动作的可证性问题。

### 二、技术方案

本发明提供一种基于零知识证明的医疗数据隐私处理可验证方法，包括：

**（一）隐私原语执行证明。**
Sidecar 内嵌证明生成器，对每个处理单元（字段、批次或记录）生成零知识执行证明，证明"输出数据确实是输入数据经指定原语与参数处理的结果"，且证明生成过程不暴露输入明文。定义执行关系：

\[
R_{exec} = \left\{ (in, out, prim, params) : out = Prim(in, params) \right\} \tag{1}
\]

处理结果按"结果数据、隐私元数据、执行凭证"三元组交付，执行凭证结构为：

\[
cert = \left( H_{in},\ H_{out},\ prim,\ params\_hash,\ meta,\ \pi_{exec},\ vk \right) \tag{2}
\]

其中 \(H_{in} = H(in)\)、\(H_{out} = H(out)\) 为输入/输出数据指纹（SHA-256），\(params\_hash\) 为原语参数哈希，\(meta\) 为隐私处理元数据（沿用 masking_metadata 等既有结构），\(\pi_{exec}\) 为执行证明，\(vk\) 为公开验证密钥。输入明文不离开证明生成域。

**（二）分类分级结果证明。**
对分级引擎输出生成等级证明，证明字段等级由公开规则集按既定逻辑计算得出：

\[
R_{grade} = \left\{ (field\_name, rules\_hash, level) : level = Engine(field\_name, Rules) \wedge rules\_hash = H(Rules) \right\} \tag{3}
\]

字段名（命名推断依据）可公开参与证明；字段值（敏感面）不作为公开 witness；规则集哈希公开，规则变更即旧凭证链失效，需重新生成分级凭证。

**（三）处理凭证与链上锚定。**
执行凭证与分级凭证经哈希摘要锚定上链：链上仅存 \(H(cert)\) 与摘要元数据（原语标识、时间戳、涉及字段名），形成不可篡改的处理账本；任意验证方以公开验证密钥 \(vk\) 离线验证凭证，无需回访处理方，也无需接触原始数据。

**（四）血缘链与聚合合规证明。**
跨系统流转时，下一节点的输入数据指纹等于上一节点的输出数据指纹：

\[
H_{in}^{(i+1)} = H_{out}^{(i)} \tag{4}
\]

各节点执行凭证按数据流构成血缘链（有向无环图 DAG），支持同一数据被多分支复用时的合规核查。对整条血缘链生成聚合合规证明：

\[
R_{policy} = \left\{ (lineage, policy) : \forall\ 字段\ l \ge l_4 \Rightarrow 已被遮蔽或门禁处理 \right\} \tag{5}
\]

监管方一次验证聚合证明，即可完成整条跨机构链路的策略合规核查，无需逐节点取证。

**（五）门禁证明。**
对最高敏档（L4/L5）门禁动作生成门禁证明，同时证实"输出确为固定占位标记"与"输入等级达到最高敏档"：

\[
R_{gate} = \left\{ (level, out) : level \ge l_4 \wedge out = [L4\text{-}L5\text{-}DATA\text{-}REMOVED] \right\} \tag{6}
\]

防止"声称门禁但实际输出残留"或"未达等级却执行替换"两类异常。

**（六）与既有元数据体系兼容。**
执行凭证与分级凭证作为列式数据表 Schema 的扩展元数据键（如 `zk_exec_proof`、`zk_grade_proof`）随 Arrow IPC 与既有的 masking_metadata、dp_metadata、k_anonymity_record_metadata、qol_metadata 共存流转——下游系统"既读又可证"，对既有消费者透明。

**（七）查询混淆索引的零知识传递（可选从属方案）。**
查询混淆结果的真实查询索引 `real_query_index` 经零知识证明传递：向不信任方证明"持有合法真实查询索引"，而不泄露索引值本身与真实查询内容。

本发明还提供实现上述方法的可验证隐私治理系统与计算机可读存储介质。

### 三、有益效果

1. **可读升级为可证**：处理声明具备密码学证据，伪造"已脱敏"元数据不再可能，缺陷节点可被自动检出。
2. **验证不触明文**：零知识证明保证证明生成与验证全程不暴露原始数据，破解"明文参与验证"的悖论。
3. **全链路零信任核查**：聚合合规证明一次验证完成跨机构链路合规，监管无需逐节点取证。
4. **分级可审计**：等级计算可验证，规则集哈希公开，规则私自放宽无法隐匿。
5. **门禁可证**：最高敏数据的整段替换动作留痕且可验证。
6. **平滑兼容**：凭证作为扩展元数据键与既有 Arrow 元数据体系共存，对既有下游消费者透明。

| 对比维度 | 最接近现有技术 | 本发明区别特征 | 带来的技术效果 |
|---|---|---|---|

| 验证方式 | 需明文重算比对，验证过程暴露隐私 | 零知识证明生成与验证全程不触明文 | 破解"明文参与验证"的隐私悖论 |
| 链路取证 | 逐节点调取内部日志，跨机构协作难 | 血缘链指纹链接 + 聚合合规证明 | 监管一次验证即完成跨机构全链路零信任核查 |

### 五、原语证明、血缘一致性与凭证生命周期

**（一）创新点强化**

1. 将“处理结果、隐私元数据、执行凭证”绑定为不可拆分的交付单元，验证者无需取得医疗明文即可验证处理关系。
2. 以输入/输出承诺形成可分叉的血缘 DAG，并用节点类型、父节点集合和策略版本约束跨机构拼接，避免仅凭 SHA-256 日志声称处理正确。
3. 将分类分级、隐私原语执行和高敏门禁纳入统一证明接口；规则集摘要改变时，旧分级凭证不能被错误复用。
4. 将证明密钥、规则版本、凭证撤销和 Arrow 传递纳入生命周期管理，使密码学凭证可运营而不仅是一次性示例。

**（二）原语证明接口**

每个证明电路声明统一接口 `Commit(in) → h_in`、`Commit(out) → h_out`、`Prim(in, params, randomness) → out`，并把原语版本、参数承诺、随机源承诺和策略摘要作为公开输入。Masking 证明字段替换关系，DP 证明敏感度裁剪、噪声承诺及预算扣减，K-匿名证明等价组大小不小于 `k`，查询混淆证明输出属于授权候选池且不公开真实索引。

随机 DP 噪声不得仅由“随机数哈希”代替正确性证明；实施时应证明随机源承诺与约定分布采样电路一致，并将噪声参数、截断规则和敏感度上界绑定到 `params_hash`。对于无法在当前证明系统中高效表示的 LLM 或复杂正则，将其转换为已签名的确定性规则摘要并标记“外部可信执行”，不得声称已证明任意 LLM 内部行为。

**（三）血缘 DAG 与门禁一致性**

每个节点凭证包含 `node_id、parent_ids、h_in、h_out、policy_hash、primitive_version、seq`。验证器检查父节点已存在、输入承诺与父输出一致、序列不回退、策略版本在允许迁移路径内，并拒绝环、重复节点和跨租户拼接。聚合证明仅聚合已经逐节点验证的关系，聚合失败时回退到可定位的节点级证明。

L4/L5 门禁证明必须同时证明输入等级达到门槛、输出为固定占位承诺、原始明文未进入交付结果；门禁失败不得用普通 masking 凭证替代。Arrow 扩展元数据只保存凭证摘要和验证端点，凭证本体可通过授权索引取回，避免 schema 泄露原始参数。

**（四）密钥生命周期、撤销与验证指标**

证明密钥、验证密钥和规则签名密钥分别管理，凭证记录 `key_id、circuit_id、version、issued_at、expires_at、revocation_ref`；电路升级采用版本兼容表，撤销或发现规则错误时按凭证索引批量标记失效。验证器默认拒绝未知电路、过期凭证、策略版本跳跃和缺少父节点的凭证。

应测试原语边界、随机性绑定、DAG 分叉合并、重放/拼接攻击、凭证撤销、Arrow 元数据篡改和聚合失败，测量证明生成时间、验证时间、凭证大小、链上摘要成本、错误定位率及明文泄露面。可从属限定：节点级错误定位、可撤销凭证、可信执行域证明、证明缓存按参数哈希失效，以及跨机构验证的租户域隔离。

## 术语与符号说明

| 术语/符号 | 含义 |
|---|---|
| 执行证明 π_exec | 证明输出 = 原语(输入, 参数) 的零知识证明 |
| 处理凭证 cert | 数据指纹、原语标识、参数哈希、元数据、证明与验证密钥的封装 |
| 数据指纹 H | 输入/输出数据的 SHA-256 哈希，链上与凭证中代替明文 |
| 分级证明 π_grade | 证明等级由公开规则集按既定逻辑计算得出的证明 |
| 规则集哈希 rules_hash | 公开规则集的哈希，规则变更即旧凭证失效 |
| 血缘链 | 按 H_in = H_out 指纹链接的跨系统处理凭证链（DAG） |
| 聚合合规证明 π_policy | 证明整条链路上高敏字段均被处理的一次性证明 |
| 门禁证明 π_gate | 同时证明输出为占位标记且输入达到最高敏档的证明 |
| 验证密钥 vk | 公开的证明验证密钥，验证方据此离线验证凭证 |
| 锚定交易 | 将凭证摘要写入链上的交易 |
| witness / statement | 零知识证明的私有输入 / 公开输入 |
| 证明生成域 | 生成证明的执行环境（进程内/可信执行环境），明文不离开该域 |
| 扩展元数据键 | Schema 中承载凭证的新键（zk_exec_proof / zk_grade_proof） |
| DAG | 有向无环图，血缘链的组织形式，支持多分支复用 |

```
              (同时证实: 输出为占位标记 ∧ 输入达最高敏档)
                          │
                          ▼
              审计日志 + 门禁凭证锚定上链

 真实查询 q ──► QoL 混淆 ──► queries + real_query_index
                                  │
                                  ▼
                   索引零知识证明: 证明持有合法真实查询索引
                   不泄露索引值 不泄露真实查询内容
```

## 具体实施方式

**实施例 1：脱敏执行证明。**
身份证字段执行掩码（保留前 6 后 4）：证明生成器生成 \(\pi_{exec}\)，证明"输出 = mask_id_card(输入)"，交付（掩码结果、masking_metadata、执行凭证）。验证方用公开 vk 验证凭证——无需获得原始身份证号即可确认掩码确已执行，伪造"已脱敏"元数据将被拒绝。

**实施例 2：DP 注噪参数证明。**
统计查询返回 DPResult 时附带执行凭证：证明"噪声尺度与声称的 ε/δ 消耗匹配（Laplace: scale = s/ε），输出为注噪后的统计值"。验证方确认参数一致性后，无法伪造"未注噪却宣称已注噪"的结果，杜绝只记账不注噪的欺骗。

**实施例 3：K-匿名泛化证明。**
整表泛化后凭证证明"输出 = 泛化(input, qi_cols, hierarchy)"，且等价类计数与 k 值声明一致；下游科研机构无需回访脱敏平台即可确认泛化层级真实、k 值未被虚报。

**实施例 4：分级结果证明。**
字段 `diagnosis` 判为 L3：凭证含公开 rules_hash 与分级证明——"按公开规则集，该字段名的等级裁定为 L3"；字段值不进入证明输入。规则升级时 rules_hash 变化，历史凭证自动失效并触发重新分级，监管可对比哈希确认规则未被私自放宽。

**实施例 5：跨机构血缘链。**
医院 A 脱敏 → 科研平台 B 泛化 → 监管 C 存档：A 的输出指纹成为 B 的输入指纹，凭证按式 (4) 链接成血缘链；三家机构的凭证摘要均锚定联盟链，任意分支节点的处理历史可追溯。

**实施例 6：聚合合规证明。**
监管方对整条血缘链执行一次聚合验证：确认链路上所有 L4+ 字段均被掩码或门禁处理、所有 L3 字段至少被一种原语处理；无需逐节点调取内部日志，零信任完成年度合规核查。

**实施例 7：门禁证明。**
基因字段判为 L5：门禁输出占位标记 + 门禁凭证；监管可验证"确为整段替换"而非"部分脱敏残留"，且替换时输入等级确达最高敏档。

**实施例 8：关键参数配置表。**

| `PRIVACY_ZK_CHAIN_ENABLED` | false | 凭证摘要锚定上链开关 |

## 摘要

本发明公开了一种基于零知识证明的医疗数据隐私处理可验证性与血缘链证明方法、系统及存储介质。该方法在隐私原语执行的同时生成零知识执行证明，证明输出确为输入经指定原语与参数处理的结果，而证明生成与验证全程不暴露输入明文；分级引擎输出附带以字段名与公开规则集哈希为公开输入的等级证明，字段值不出域；执行凭证与分级凭证以数据指纹链接成跨系统血缘链并锚定上链，形成不可篡改的处理账本；对整条血缘链生成聚合合规证明，监管方一次验证即可完成全链路策略合规核查；最高敏感档门禁动作附带门禁证明，确保整段替换确已执行。本发明将隐私处理的"可读审计"升级为"可验证审计"，实现跨机构零信任合规核查。
