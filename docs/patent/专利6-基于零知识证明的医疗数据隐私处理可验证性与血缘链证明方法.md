**缩略语和关键术语定义列表（交底书中如有的话，请说明）**

> 1、零知识证明（Zero-Knowledge Proof，ZKP）：证明者能够在不向验证者泄露任何有用信息的情况下，使验证者相信某个论断是正确的密码学协议。
>
> 2、隐私原语（Privacy Primitives）：本发明中对待处理数据实施隐私保护的基础算法或操作单元，主要包括智能遮蔽、差分隐私注噪、K-匿名泛化与查询混淆。
>
> 3、差分隐私（Differential Privacy，DP）：通过在查询或统计结果中添加受控随机噪声，使得单条记录的存否难以被推断的隐私保护模型。
>
> 4、K-匿名（K-Anonymity）：一种数据匿名化准则，要求发布数据中的每条记录在准标识符属性上至少与另外 K-1 条记录不可区分。
>
> 5、查询混淆（Query Obfuscation，QoL）：在真实查询之外混入虚假查询，以隐藏真实查询意图的隐私增强技术。
>
> 6、Apache Arrow 列式交换格式（Arrow IPC）：一种跨语言、跨进程的列式数据内存格式，本发明中以 Arrow IPC 作为医疗数据跨系统流转的载体。
>
> 7、有向无环图（Directed Acyclic Graph，DAG）：由节点和有向边组成且不存在环路的图结构，本发明中用于组织跨系统处理凭证的血缘关系。
>
> 8、安全散列算法256位（Secure Hash Algorithm 256-bit，SHA-256）：一种密码学哈希函数，用于生成本发明中的数据指纹与凭证摘要。
>
> 9、可信执行环境（Trusted Execution Environment，TEE）：处理器中提供硬件级隔离的执行区域，用于保护证明生成过程中的明文输入。
>
> 10、见证/陈述（Witness / Statement）：零知识证明中的私有输入（witness）与公开输入（statement）。

1.  **相关技术背景（背景技术），与本发明最相近似的现有实现方案（现有技术）**

1.1 背景技术

医疗数据在诊疗、科研、公共卫生等场景间高频流转，其隐私治理已成为行业监管与合规审计的核心需求。典型的隐私治理流程包括：对原始医疗数据执行分类分级，识别姓名、身份证号、诊断、基因等敏感字段；再依据分级结果调用隐私原语（如智能遮蔽、差分隐私注噪、K-匿名泛化、查询混淆等）对数据进行处理；最后将处理结果交付下游系统使用。

在上述流程中，数据接收方与监管方需要确认“数据确实已被声明的隐私原语按声明参数处理过”。传统做法是随数据携带隐私处理元数据，例如将 `masking_metadata`、`dp_metadata`、`k_anonymity_record_metadata`、`qol_metadata` 等作为 Apache Arrow 列式交换格式（Arrow IPC）Schema 的扩展元数据随数据一起流转。该方式能够说明“下游数据经历了何种处理”，但元数据本身只是可读的声明，并不具备密码学证据效力。

随着跨机构协作与“零信任”合规审计要求的提出，业界迫切需要一种在“不暴露原始明文”的前提下，对隐私处理行为、分类分级结果、高敏感数据门禁动作以及跨系统处理链路进行密码学验证的技术方案。

1.2 与本发明相关的现有技术一

1.2.1 现有技术一的技术方案

与本发明最接近的现有技术为“基于元数据嵌入的隐私处理可读审计方案”（对应本系列专利 4 所描述的技术）。该方案将隐私处理产生的元数据嵌入 Arrow IPC 的 Schema 中，使下游消费者能够直接读取某字段是否经过掩码、差分隐私（Differential Privacy，DP）注噪、K-匿名（K-Anonymity）泛化或查询混淆（Query Obfuscation，QoL）处理。元数据随数据一起跨系统流转，监管方可以通过解析 Arrow Schema 查看处理声明，从而完成形式上的合规审查。

其基本处理单元为“处理结果 + 隐私元数据”二元组，数据在不同系统之间以 Arrow IPC 消息形式传递，元数据以键值对形式附加在列式 Schema 上。监管方或下游系统读取元数据后即可知悉上游声称执行了何种隐私处理。

1.2.2 现有技术一的缺点

（1）**元数据可读不可证**。下游读取的“已脱敏”声明仅是一段文本或结构化数据，无法被密码学验证。恶意节点或存在缺陷的节点可伪造元数据并宣称已执行隐私处理，而实际输出中仍残留明文；元数据与数据同源产出，缺失独立的验证通道。

（2）**明文参与验证的悖论**。若以原始数据参与校验（例如重算脱敏结果并与输出比对），则验证过程本身会暴露明文，与隐私保护目标直接矛盾；若完全不经校验，则无法发现“宣称已处理、实际未处理”的缺陷。

（3）**跨系统链路取证成本高**。监管方需要接触每个节点的内部日志才能确认处理真实发生，跨机构协作困难、取证周期长，无法支撑“零信任”合规核查。

（4）**分级结果不可验证**。业务系统宣称“字段为 L3”或“字段为 L4/L5”，监管方无法确认该等级是由既定规则集正确计算得出，也无法发现规则是否被私自放宽。

（5）**门禁动作无证据**。最高敏感档（L4/L5）数据的整段替换动作缺乏可验证证据，无法证明“确已替换而非部分残留”，也无法证明替换时输入等级确实达到最高敏感档。

1.3 与本发明相关的现有技术二

1.3.1 现有技术二的技术方案

现有技术二为“基于明文重算与集中式审计日志的隐私处理验证方案”。该方案在处理节点本地记录完整审计日志，包括输入数据、处理参数、输出数据、操作人、时间戳等；监管方或验证方在需要合规核查时，向处理节点申请调取日志，并在本地对关键记录进行重算比对，以确认处理结果与声明一致。部分改进方案还会对日志做哈希摘要并集中存储于数据库或区块链，用于防篡改。

1.3.2 现有技术二的缺点

（1）**验证过程泄露隐私**。重算比对必须以原始明文或准标识符作为输入，验证方因此能够接触到本不应查看的敏感医疗数据，违反最小必要原则。

（2）**信任根集中在处理节点**。日志由处理节点自行生成并保管，节点可在日志层面造假或选择性删除；集中式哈希日志只能证明“日志未被事后篡改”，无法证明“日志内容本身真实反映了处理行为”。

（3）**跨机构审计效率低**。监管方需要逐节点调取、解析、比对日志，链路越长审计成本越高，且不同机构的数据格式与日志规范难以统一。

（4）**无法验证规则执行正确性**。现有日志方案记录的是处理动作，无法以密码学方式证明“字段等级由某版本的规则集按既定逻辑计算得出”。

2.  **本发明技术方案的详细阐述（发明内容）**

2.1 本发明所要解决的技术问题（发明目的）

针对上述现有技术的不足，本发明所要解决的技术问题包括：

（1）解决隐私处理声明“可读不可证”的问题，使处理声明具备密码学证据，防止伪造“已脱敏”元数据；

（2）解决验证过程暴露明文的问题，使验证方在不接触原始医疗数据的前提下确认处理行为的真实性；

（3）解决跨系统全链路合规取证的零信任问题，使监管方无需逐节点取证即可完成整条跨机构链路的合规核查；

（4）解决分级结果正确性验证的问题，使字段敏感度等级可由公开规则集以可验证方式计算得出，并防止规则被私自放宽；

（5）解决最高敏感档门禁动作的可证性问题，使整段替换动作留下可验证证据，并证明替换时输入等级确已达到最高敏感档；

（6）在保证上述能力的同时，与现有基于 Arrow IPC 的隐私元数据体系保持兼容，对既有下游消费者透明。

2.2 本发明提供的完整技术方案（发明方案）

2.2.1 系统组成与总体架构

本发明提供一种基于零知识证明（Zero-Knowledge Proof，ZKP）的医疗数据隐私处理可验证性与血缘链证明方法、系统以及计算机可读存储介质。系统主要由以下模块组成：

- **分类分级引擎**：对输入医疗数据字段执行分类分级，输出字段敏感度等级以及分级证明；
- **隐私原语执行器**：按策略调用智能遮蔽、差分隐私（Differential Privacy，DP）注噪、K-匿名（K-Anonymity）泛化、查询混淆（Query Obfuscation，QoL）等原语；
- **零知识证明生成器**：为原语执行结果、分级结果、门禁动作生成零知识证明，并确保明文不离开证明生成域；
- **凭证封装模块**：将处理结果、隐私元数据与执行证明封装为处理凭证；
- **链上锚定模块**：将凭证摘要写入区块链或分布式账本，形成不可篡改的处理账本；
- **血缘链构建模块**：按输入/输出数据指纹链接跨节点处理凭证，形成有向无环图（Directed Acyclic Graph，DAG）形式的血缘链；
- **聚合合规证明模块**：对整条血缘链生成聚合零知识证明，供监管方一次性验证；
- **离线验证器**：供任意验证方使用公开验证密钥离线验证各类证明与凭证。

2.2.2 隐私原语执行证明

对每个处理单元（字段、批次或记录），零知识证明生成器构造执行关系：

\[
R_{exec} = \left\{ (in, out, prim, params) : out = Prim(in, params) \right\} \tag{1}
\]

其中，\(in\) 为输入数据，\(out\) 为输出数据，\(prim\) 为原语标识，\(params\) 为原语参数。证明生成器生成执行证明 \(\pi_{exec}\)，证明“输出数据确实是输入数据经指定原语与参数处理的结果”，且证明生成过程不暴露输入明文。

处理结果按“结果数据、隐私元数据、执行凭证”三元组交付。执行凭证结构为：

\[
cert = \left( H_{in},\ H_{out},\ prim,\ params\_hash,\ meta,\ \pi_{exec},\ vk \right) \tag{2}
\]

其中 \(H_{in} = H(in)\)、\(H_{out} = H(out)\) 为输入/输出数据指纹（采用安全散列算法256位（Secure Hash Algorithm 256-bit，SHA-256）生成），\(params\_hash\) 为原语参数哈希，\(meta\) 为隐私处理元数据，\(\pi_{exec}\) 为执行证明，\(vk\) 为公开验证密钥。输入明文不离开证明生成域。

隐私原语执行证明生成与交付流程如图 2 所示。

```mermaid
graph TB
    A[输入数据 in 明文] --> B[隐私原语执行 out = Prim(in, params)]
    B --> C[证明生成器 π_exec = Prove(R_exec, in, out, params)]
    C --> D[明文不离开证明生成域]
    C --> E[数据指纹 H_in H_out]
    E --> F[凭证 cert = H_in|H_out|prim|params_hash|meta|π_exec|vk]
    F --> G[交付三元组 结果 + 元数据 + 凭证]
    F --> H[凭证摘要 H(cert) 锚定上链]
    H --> I[验证方持 vk 离线验证 无需回访]
```

2.2.3 分类分级结果证明

对分级引擎输出，本发明生成等级证明，证明字段等级由公开规则集按既定逻辑计算得出。分级关系定义为：

\[
R_{grade} = \left\{ (field\_name, rules\_hash, level) : level = Engine(field\_name, Rules) \wedge rules\_hash = H(Rules) \right\} \tag{3}
\]

其中，\(field\_name\) 为字段名（命名推断依据），可公开参与证明；\(Rules\) 为规则集；\(rules\_hash = H(Rules)\) 为规则集哈希，公开可对比；\(level\) 为计算出的敏感度等级。字段值作为敏感面不作为公开输入（witness），仅字段名与规则集哈希进入公开陈述（statement）。规则集哈希随规则变更而更新，旧凭证在规则集哈希变化后失效，需重新生成分级凭证。

分类分级结果证明流程如图 3 所示。

```mermaid
graph TB
    A[字段名 + 规则集 Rules] --> B[分级引擎 level = Engine(field_name, Rules)]
    B --> C[rules_hash = H(Rules) 公开可对比]
    C --> D[分级证明 π_grade = Prove(R_grade, level, rules_hash)]
    D --> E[字段值不参与公开 witness 敏感面不出域]
    E --> F[等级 + 分级凭证交付下游]
    F --> G[规则变更 → 哈希变化 → 旧凭证失效 重新分级]
```

2.2.4 处理凭证与链上锚定

执行凭证与分级凭证经哈希摘要后锚定上链。链上仅存 \(H(cert)\) 与摘要元数据（原语标识、时间戳、涉及字段名等），形成不可篡改的处理账本。任意验证方使用公开验证密钥 \(vk\) 即可离线验证凭证，无需回访处理方，也无需接触原始数据。

凭证摘要锚定过程由链上锚定模块完成，链上数据仅用于时序固化与抗抵赖，原始明文、证明本体与详细参数均不上链，从而避免链上隐私泄露。

2.2.5 血缘链与聚合合规证明

跨系统流转时，下一处理节点的输入数据指纹等于上一节点的输出数据指纹：

\[
H_{in}^{(i+1)} = H_{out}^{(i)} \tag{4}
\]

各节点执行凭证按数据流构成血缘链。为支持同一数据被多分支复用时的合规核查，血缘链以有向无环图（Directed Acyclic Graph，DAG）形式组织。每个节点凭证至少包含 `node_id`、`parent_ids`、`h_in`、`h_out`、`policy_hash`、`primitive_version`、`seq` 等字段。血缘链构建模块验证父节点存在性、输入承诺与父输出一致性、序列不回退、策略版本在允许迁移路径内，并拒绝环路、重复节点和跨租户拼接。

对整条血缘链生成聚合合规证明：

\[
R_{policy} = \left\{ (lineage, policy) : \forall\ 字段\ l \ge l_4 \Rightarrow 已被遮蔽或门禁处理 \right\} \tag{5}
\]

监管方一次验证聚合证明，即可完成整条跨机构链路的策略合规核查，无需逐节点取证。聚合证明仅聚合已经逐节点验证的关系，聚合失败时可回退到可定位的节点级证明。

血缘链 DAG 构建与聚合合规证明如图 4 所示。

```mermaid
graph TB
    A[节点1 凭证 cert1] --> B[输出指纹 H_out1]
    B --> C[节点2 输入指纹 H_in2 = H_out1 链接]
    C --> D[节点2 凭证 cert2]
    D --> E[节点3 输入 H_in3 = H_out2]
    E --> F[节点N 凭证 certN]
    F --> G[血缘链 DAG 完整 支持多分支复用]
    G --> H[聚合证明 π_policy = Prove(R_policy, lineage)]
    H --> I[监管一次验证 = 整条链路合规]
```

2.2.6 门禁证明

对最高敏感档（L4/L5）数据，本发明执行整段替换并生成门禁证明，同时证实“输出确为固定占位标记”与“输入等级达到最高敏感档”。门禁关系为：

\[
R_{gate} = \left\{ (level, out) : level \ge l_4 \wedge out = [L4\text{-}L5\text{-}DATA\text{-}REMOVED] \right\} \tag{6}
\]

门禁证明防止“声称门禁但实际输出残留”或“未达等级却执行替换”两类异常。L4/L5 门禁证明必须同时证明输入等级达到门槛、输出为固定占位承诺、原始明文未进入交付结果；门禁失败不得用普通遮蔽凭证替代。

2.2.7 与既有元数据体系兼容

执行凭证与分级凭证作为列式数据表 Schema 的扩展元数据键（例如 `zk_exec_proof`、`zk_grade_proof`）随 Arrow IPC 流转，与既有的 `masking_metadata`、`dp_metadata`、`k_anonymity_record_metadata`、`qol_metadata` 共存。下游系统“既读又可证”，对既有消费者透明。Arrow 扩展元数据中仅保存凭证摘要与验证端点，凭证本体可通过授权索引取回，避免 Schema 泄露原始参数。

2.2.8 查询混淆索引的零知识传递

对于查询混淆结果，真实查询索引 `real_query_index` 经零知识证明传递：向不信任方证明“持有合法真实查询索引”，而不泄露索引值本身与真实查询内容。该从属方案适用于需要向外部服务证明查询合法性，但又不能暴露真实查询意图的场景。

门禁证明与查询索引零知识传递流程如图 5 所示。

```mermaid

    C --> D[审计日志 + 门禁凭证锚定]

```

2.2.9 原语证明接口、随机性绑定与生命周期管理

每个证明电路声明统一接口：`Commit(in) → h_in`、`Commit(out) → h_out`、`Prim(in, params, randomness) → out`，并把原语版本、参数承诺、随机源承诺和策略摘要作为公开输入。不同隐私原语的证明内容分别验证：

- **智能遮蔽**：证明字段替换函数正确性；
- **差分隐私**：证明噪声尺度与预算消耗匹配（例如 Laplace 机制下 `scale = s/ε`），输出确为注噪后的统计值；
- **K-匿名**：证明泛化层级与等价类计数一致性，等价组大小不小于 `k`；
- **查询混淆**：证明输出属于授权候选池，且真实索引记录正确。

随机 DP 噪声不得仅由“随机数哈希”代替正确性证明；实施时应证明随机源承诺与约定分布采样电路一致，并将噪声参数、截断规则和敏感度上界绑定到 `params_hash`。对于无法在当前证明系统中高效表示的大语言模型（Large Language Model，LLM）或复杂正则，将其转换为已签名的确定性规则摘要并标记“外部可信执行”，不得声称已证明任意 LLM 内部行为。

证明密钥、验证密钥和规则签名密钥分别管理。凭证记录 `key_id`、`circuit_id`、`version`、`issued_at`、`expires_at`、`revocation_ref`；电路升级采用版本兼容表，撤销或发现规则错误时按凭证索引批量标记失效。验证器默认拒绝未知电路、过期凭证、策略版本跳跃和缺少父节点的凭证。

关键参数配置如表 1 所示。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `PRIVACY_ZK_PROOF_ENABLED` | false | 执行/分级证明生成总开关 |
| `PRIVACY_ZK_CHAIN_ENABLED` | false | 凭证摘要锚定上链开关 |
| `PRIVACY_ZK_PROOF_SCHEME` | groth16 | 证明系统选择（groth16/bulletproofs 等） |
| `PRIVACY_ZK_RULES_HASH` | 空 | 公开规则集哈希（分级证明比对基准） |
| `PRIVACY_ZK_PROOF_CACHE` | 1024 | 同参数处理结果的证明缓存容量 |
| `PRIVACY_ZK_PROOF_CACHE_TTL` | 3600 | 证明缓存有效期（秒） |

在部署与验证阶段，应针对原语边界、随机性绑定、DAG 分叉合并、重放/拼接攻击、凭证撤销、Arrow 元数据篡改和聚合失败等场景进行测试，并测量证明生成时间、验证时间、凭证大小、链上摘要成本、错误定位率及明文泄露面。可从属限定包括：节点级错误定位、可撤销凭证、可信执行域证明、证明缓存按参数哈希失效，以及跨机构验证的租户域隔离。

2.2.10 具体实施示例

**实施例 1：脱敏执行证明**。身份证字段执行掩码（保留前 6 后 4）：证明生成器生成 \(\pi_{exec}\)，证明“输出 = mask_id_card(输入)”，交付（掩码结果、masking_metadata、执行凭证）。验证方用公开 `vk` 验证凭证——无需获得原始身份证号即可确认掩码确已执行，伪造“已脱敏”元数据将被拒绝。

**实施例 2：DP 注噪参数证明**。统计查询返回 DPResult 时附带执行凭证：证明“噪声尺度与声称的 ε/δ 消耗匹配（Laplace: scale = s/ε），输出为注噪后的统计值”。验证方确认参数一致性后，无法伪造“未注噪却宣称已注噪”的结果。

**实施例 3：K-匿名泛化证明**。整表泛化后凭证证明“输出 = 泛化(input, qi_cols, hierarchy)”，且等价类计数与 k 值声明一致；下游科研机构无需回访脱敏平台即可确认泛化层级真实、k 值未被虚报。

**实施例 4：分级结果证明**。字段 `diagnosis` 判为 L3：凭证含公开 `rules_hash` 与分级证明——“按公开规则集，该字段名的等级裁定为 L3”；字段值不进入证明输入。规则升级时 `rules_hash` 变化，历史凭证自动失效并触发重新分级。

**实施例 5：跨机构血缘链**。医院 A 脱敏 → 科研平台 B 泛化 → 监管 C 存档：A 的输出指纹成为 B 的输入指纹，凭证按式 (4) 链接成血缘链；三家机构的凭证摘要均锚定联盟链，任意分支节点的处理历史可追溯。

**实施例 6：聚合合规证明**。监管方对整条血缘链执行一次聚合验证：确认链路上所有 L4+ 字段均被掩码或门禁处理、所有 L3 字段至少被一种原语处理；无需逐节点调取内部日志，零信任完成年度合规核查。

**实施例 7：门禁证明**。基因字段判为 L5：门禁输出占位标记 + 门禁凭证；监管可验证“确为整段替换”而非“部分脱敏残留”，且替换时输入等级确达最高敏感档。

本发明技术方案带来的有益效果包括：

（1）**可读升级为可证**。处理声明具备密码学证据，伪造“已脱敏”元数据不再可能，缺陷节点可被自动检出。

（5）**门禁可证**。最高敏感档数据的整段替换动作留痕且可验证。

（6）**平滑兼容**。凭证作为扩展元数据键与既有 Arrow IPC 元数据体系共存，对既有下游消费者透明。

3.  **针对2中的技术方案，是否还有别的替代方案同样能完成发明目的**

除上述优选方案外，还存在以下替代方案，可同样完成发明目的：

（1）**证明系统替代**。零知识证明生成器可采用 Groth16、Bulletproofs、Plonk、STARKs 等不同证明系统；不同系统在证明大小、验证时间、可信设置需求上各有优劣，可依据部署环境选择。

（2）**承诺机制替代**。数据指纹除采用 SHA-256 外，也可采用 Merkle 树根、Pedersen 承诺、Poseidon 哈希等密码学承诺，以适应不同电路友好性需求。

（3）**链上锚定替代**。凭证摘要除写入区块链或联盟链外，也可写入分布式身份标识符（Decentralized Identifier，DID）可验证凭证、分布式文件系统的版本控制日志，或经多方安全计算共同维护的只增日志中。

（4）**血缘链组织替代**。血缘链除采用 DAG 外，也可采用线性哈希链、Merkle DAG 或基于事件溯源的日志结构；在单分支场景下，线性链足以表达处理顺序。

（5）**证明生成环境替代**。证明生成可在可信执行环境（Trusted Execution Environment，TEE）中完成，也可在进程内安全沙箱中完成；对于复杂原语或外部模型，可结合 TEE 与规则签名形成“外部可信执行”凭证。

（6）**门禁占位标记替代**。固定占位标记除 `[L4-L5-DATA-REMOVED]` 外，也可采用零长度字符串、标准化令牌或经哈希隐藏的标记值，只要验证电路能识别其等价形式。

（7）**缓存策略替代**。证明缓存除按参数哈希建立 LRU 缓存外，也可采用确定性再生成、预热缓存或分布式缓存；缓存失效策略可与规则版本、密钥版本联动。

4.  **本发明的技术关键点和欲保护点是什么？**

本发明的技术关键点和欲保护点包括：

（1）将“处理结果、隐私元数据、执行凭证”绑定为不可拆分的交付单元，验证者无需取得医疗明文即可验证处理关系。

（2）以输入/输出承诺形成可分叉的血缘 DAG，并用节点类型、父节点集合和策略版本约束跨机构拼接，避免仅凭 SHA-256 日志声称处理正确。

（3）将分类分级、隐私原语执行和最高敏感档门禁纳入统一证明接口；规则集摘要改变时，旧分级凭证不能被错误复用。

（4）将证明密钥、规则版本、凭证撤销和 Arrow IPC 传递纳入生命周期管理，使密码学凭证可运营而不仅是一次性示例。

（5）对差分隐私等随机化原语，将随机源承诺、噪声参数、截断规则与敏感度上界绑定到 `params_hash`，防止以“随机数哈希”冒充正确性证明。

（6）对无法高效电路化的大语言模型或复杂正则，采用已签名的确定性规则摘要并标记“外部可信执行”，避免对不可证明行为虚假声称已证明。

（7）最高敏感档门禁证明必须同时证明输入等级达到门槛、输出为固定占位承诺、原始明文未进入交付结果，并禁止以普通遮蔽凭证替代门禁凭证。

（8）聚合合规证明在节点级证明已验证的基础上进行聚合，失败时支持回退到节点级证明，实现可定位的全链路零信任核查。
