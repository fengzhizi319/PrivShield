# 专利草案 01：面向医疗数据分类分级的图像多模态安全打码与文本脱敏联动方法

## 一、创新点提炼（与已有专利的差异定位）

> 已有中文专利 1 已覆盖三层漏斗文本/记录分类分级、安全地板、置信度策略、冲突检测、LLM 仲裁等核心机制；已有中文专利 4 已覆盖 Sidecar 架构下的分类分级驱动隐私原语编排与 Arrow 元数据流转。本专利草案聚焦于**医学影像/图像输入的识别、多模态分类、安全打码**，以及**分类结果与文本脱敏、图像打码的跨模态联动**，与上述专利形成互补。

1. **三层信号的图像输入识别机制**
   - 不仅依赖文件扩展名，还综合检测字段值是否以 `data:image/` 或 `image:` 前缀开头（Base64 内联图像），以及字段名是否包含图像/DICOM/X-Ray/CT/MRI/切片等中英文语义标识。
   - 对字段名语义检测设置反例过滤：值长度 ≤ 3 或值为 http(s) URL 时排除，避免将“图片链接说明文本”误判为图像输入。

2. **医学影像多模态分类分级**
   - 对识别出的图像/DICOM/医学影像输入，自动触发多模态 LLM 层进行视觉内容分析，输出敏感等级、置信度与推理说明。
   - 多模态 LLM 输出同样受“安全地板”约束：裁定等级不得低于上游规则/NER 已确定等级，未返回合法等级时不刷新置信度并标记人工复核。

3. **fail-closed 的图像打码安全沙箱**
   - 输入路径经 `resolve()` 解析后，必须位于 `PRIVACY_IMAGE_ALLOWED_DIRS` 白名单目录前缀内；通过前缀匹配拦截目录穿越与 symlink 逃逸。
   - 图像尺寸限制：`MAX_IMAGE_PIXELS` 防止 decompression bomb；超过 2048×2048 自动采用 LANCZOS 下采样防止 OOM。
   - DICOM 等无法安全派生为普通图像的格式，直接返回 `[IMAGE-REDACTION-FAILED]` 失败占位，避免解析漏洞。

4. **区域化敏感内容遮挡**
   - 默认遮挡策略：图像顶部 16% 与底部 18%，覆盖常见病历/影像中的姓名、诊断文字、签名区域。
   - 支持自定义 `boxes` 参数，以比例或像素坐标指定敏感区域。
   - 输出产物采用 sha256 前 12 位匿名命名，原子替换原文件；Base64 输入统一输出 PNG 格式。

5. **分类分级与跨模态脱敏联动**
   - 文本字段根据分类等级调用字段名感知 masking（L3 掩码、L4 泛化替换、L5 完全遮蔽/HMAC 哈希）。
   - 图像字段根据分类等级触发 image_redaction，L5 级图像直接整段替换为占位标记或全图遮蔽。
   - 在单次 `classify_field(field_name, value, sanitize=True)` 调用中，同时完成分类分级、文本脱敏与图像打码，输出 `FunnelResult.sanitized_value`。

6. **结果可审计与下游可追溯**
   - 图像打码操作记录结构化日志，包括输入类型、输出路径、是否命中白名单、是否下采样、遮挡策略等。
   - 通过 `FunnelResult` 携带 `engine_layer`（`L3_LLM` 表示多模态 LLM 来源）、`needs_human_review`、`reasoning` 与 `sanitized_value`，供下游系统审计。

## 二、专利原文

### 发明名称

一种面向医疗数据分类分级的图像多模态安全打码与文本脱敏联动方法及系统

### 技术领域

本发明涉及数据安全技术领域，尤其涉及医疗影像数据的多模态分类分级、图像安全打码、路径沙箱防护与跨模态隐私脱敏。

### 背景技术

医疗数据中不仅包含结构化和非结构化文本，还包含大量医学影像（DICOM、CT、MRI、X-Ray、病理切片、病例图片等）。现有文本分类分级技术难以直接处理图像输入，而传统图像脱敏方法存在以下问题：
1. 仅依赖文件扩展名判断图像类型，容易漏检 Base64 内联图像或字段名暗示的图像输入。
2. 对医学影像直接进行通用 OCR 或像素级处理，可能因解析复杂格式（如 DICOM）引入安全漏洞。
3. 缺乏对图像路径的严格沙箱校验，存在目录穿越、symlink 逃逸导致任意文件读取的风险。
4. 图像脱敏与文本分类分级结果割裂，无法根据敏感等级动态选择打码强度。
5. 图像处理可能引发 decompression bomb 或 OOM，导致服务拒绝服务。

### 发明内容

本发明提供一种面向医疗数据分类分级的图像多模态安全打码与文本脱敏联动方法及系统，通过三层信号识别图像输入、多模态 LLM 分类分级、fail-closed 图像沙箱与区域化遮挡，实现文本与图像的跨模态隐私治理。

一种面向医疗数据分类分级的图像多模态安全打码与文本脱敏联动方法，包括：
- 接收待分类字段，所述字段包含字段名与字段值；
- 基于文件扩展名、Base64/内联图像前缀、字段名图像语义标识三个信号识别字段值是否为图像/医学影像输入；
- 若识别为图像输入，触发多模态大语言模型对图像内容进行敏感分类分级，输出候选等级、置信度与推理说明；
- 对多模态模型输出执行安全地板校验，包括等级有效性校验、不低于上游已确定等级的降级拒绝校验、置信度安全归一化；
- 当调用方请求脱敏时，根据最终敏感等级对文本字段执行字段名感知脱敏，对图像字段执行安全沙箱校验与区域化敏感内容遮挡；
- 输出最终敏感等级、置信度、决策引擎来源、是否需要人工复核、以及脱敏产物。

进一步地，所述图像输入识别包括：
- 文件扩展名信号：字段值以 `.jpg`、`.jpeg`、`.png`、`.bmp`、`.webp`、`.dcm`、`.dicom`、`.tiff` 等扩展名结尾；
- Base64/内联图像前缀信号：字段值以 `data:image/` 或 `image:` 前缀开头；
- 字段名语义信号：字段名包含英文 `image`、`photo`、`pic`、`picture`、`dicom`、`xray`、`ct_scan`、`mri`、`img` 词边界匹配，或中文 `切片`、`病例图片`、`影像` 子串；且字段值长度大于 3 且非 http(s) URL。

进一步地，所述安全沙箱校验包括：
- 解析字段值为绝对路径；
- 检查路径是否位于 `PRIVACY_IMAGE_ALLOWED_DIRS` 环境变量配置的目录白名单内；
- 对解析后的路径重新校验前缀，防止 symlink 目标逃逸至白名单之外；
- 若校验失败，返回 `[IMAGE-REDACTION-FAILED]` 失败占位。

进一步地，所述区域化敏感内容遮挡包括：
- 默认遮挡：图像顶部 16% 区域与底部 18% 区域；
- 自定义遮挡：接收 `boxes` 参数，以相对比例或绝对像素坐标指定敏感区域；
- 遮挡方式：以纯色块或模糊核覆盖敏感区域；
- 对 DICOM 或无法安全派生为普通图像的格式，直接返回失败占位。

进一步地，所述图像处理还包括资源防护：
- 设置 `MAX_IMAGE_PIXELS` 上限，防止 decompression bomb；
- 当图像宽或高超过 2048 时，采用 LANCZOS 算法下采样；
- 输出文件采用 sha256 前 12 位匿名命名，并执行原子替换；
- Base64 输入统一输出 PNG 格式；
- 自动清理超过 200 个旧文件防止磁盘占满。

进一步地，所述跨模态脱敏联动包括：
- 对文本字段：根据字段名识别类型并执行掩码、泛化、HMAC 哈希或完全遮蔽；
- 对图像字段：根据最终敏感等级选择打码强度，L5 级图像整段替换为固定占位标记或全图遮蔽；
- 在单次调用中同时返回分类分级结果与 `sanitized_value`。

### 具体实施方式

**图像输入识别实施例**
- 字段名 `patient_avatar`、值 `/data/images/123.jpg` → 命中扩展名信号与字段名语义信号。
- 字段名 `dicom_file`、值 `data:image/png;base64,iVBORw0KGgo...` → 命中 Base64 前缀信号与字段名语义信号。
- 字段名 `image_url`、值 `http://example.com/ct.jpg` → 字段名语义命中但值为 http URL，反例过滤排除。
- 字段名 `report_note`、值 "影像显示肺部结节" → 字段名不含图像语义标识且值非图像路径，不触发图像处理。

**多模态 LLM 分类实施例**
- 输入 DICOM 影像路径，多模态 LLM 输出 `{final_level: "L4", confidence: 0.92, reasoning: "影像包含患者姓名与诊断文字"}`。
- 若上游规则已判定该字段为 L5（基因/生物特征级），则 LLM 输出 L4 被安全地板拒绝，保留 L5 并标记人工复核。

**图像打码实施例**
- 输入：文件路径 `/data/images/case_123.jpg`，分类结果 L4。
- 沙箱校验：`/data/images` 在白名单内，通过。
- 加载图像：尺寸 3000×4000，超过 2048，下采样至 1500×2000。
- 默认遮挡：顶部 16%（y: 0-320）与底部 18%（y: 1640-2000）覆盖为黑色块。
- 输出：保存至 `/data/sanitized_images/a3f7b2c9d8e1.png`，文件名由 sha256 前 12 位生成，并原子替换原文件引用。

**DICOM 失败处理实施例**
- 输入 DICOM 文件 `/data/dicom/scan.dcm`。
- 系统检测到无法安全派生为普通图像，返回 `[IMAGE-REDACTION-FAILED]`，分类结果不受影响，仅脱敏产物缺失。

**跨模态联动实施例**
- 调用 `classify_field(field_name="dicom_image", value="/data/dicom/ct.dcm", sanitize=True)`。
- 触发图像识别 → 多模态 LLM → 安全地板 → 最终等级 L4。
- 图像打码失败（DICOM），`sanitized_value = "[IMAGE-REDACTION-FAILED]"`；文本脱敏不触发（值为图像路径）。
- 返回 `FunnelResult` 包含 `final_level=L4`、`engine_layer=L3_LLM`、`needs_human_review=false`、`sanitized_value`。

### 摘要

本发明公开一种面向医疗数据分类分级的图像多模态安全打码与文本脱敏联动方法及系统。该方法通过文件扩展名、Base64 前缀、字段名语义三层信号识别图像/医学影像输入，触发多模态大语言模型进行视觉敏感分类，并施加大模型安全地板校验；对图像字段执行目录白名单沙箱校验、资源防护与区域化敏感内容遮挡，对文本字段执行字段名感知脱敏；在单次调用中完成跨模态分类与脱敏联动。本发明解决了医学影像输入漏检、图像解析安全风险、以及图像脱敏与文本分类分级割裂的问题，适用于电子病历附件、DICOM 影像、病例图片等医疗图像数据的隐私治理。
