# 医疗敏感数据全流程治理流水线 — 产品需求文档 (PRD)

> **文档版本**: 1.0  
> **面向对象**: 产品经理、项目经理、数据合规官、架构师  
> **核心痛点**: 医疗电子病历与残疾人评估数据共享时，混杂大量个人身份信息 (PII) 以及特高敏感级病史（如 HIV、恶性肿瘤、重度精神障碍），传统单一掩码脱敏无法满足国家数据安全合规要求。

---

## 1. 背景与目标

### 1.1 业务背景
在医疗数据共享、医保数据跨域结算及残疾人评估辅助决策场景中，研发与测试环境需要大量高精度的仿真医疗数据。同时，数据发布前必须经过严格的分类分级标注与脱敏清洗，防止原始患者身份与特高高危病史泄漏。

### 1.2 项目目标
1. **仿真数据自动化生成**: 提供 `scripts/data/generate_medical_data.py` 脚本，自动生成符合 GB 11643-1999 标准的真实校验码身份证号、包含图文病例引用及 L4/L5 敏感病史的标准 CSV 数据（脚本默认 20 条，仓库预置样例为 100 条，`--count` 可调）。
2. **端到端治理 Pipeline**: 组合 `dynclassification`（3-Layer 分类分级）与 `privacy/masking`（脱敏与高敏剥离），实现一键式治理。
3. **双重输出合规保障**: 治理过程生成 (1) 字段级与记录级分类分级报告 (`classification_report`)，以及 (2) 100% 剥离 L4/L5 原始词汇与 PII 掩码后的合规清洗数据 (`sanitized_data`)。
4. **全栈控制台联调**: 在 Web 控制台提供独立的“医疗敏感数据治理”功能面板，支持 Python 后端与 Go 后端双通道流畅调用。

---

## 2. 字段分级规范 (27 个核心字段)

| | 身份证号 | `id_card_no` | **L4 (极高敏感)** | 18 位格式保频掩码（如 `110101********1237`） |
| | 户口地址 | `registered_address` | **L3 (高敏感)** | 地址掩码 / 泛化到地级市 |

| | 医保证号 | `medical_insurance_no` | **L3 (高敏感)** | 社保号保频掩码 |
| **人口学** | 性别 | `gender` | **L1 (公开)** | 保持原样 |
| | 年龄 | `age` | **L1 (公开)** | 保持原样 / 区间化 |
| **临床诊断与病历** | 诊断名称 | `diagnosis_name` | **L4~L5 (特高敏感)** | **L4/L5 强剥离** (替换为 `[L5-IMMUNODEFICIENCY-SENSITIVE-MASKED]` 等) |

| | 个人史 | `personal_history` | **L2 (低敏感)** | 保持原样 / 规约 |
| | 是否吸烟 | `is_smoking` | **L1 (公开)** | 保持原样 |

| | 评估结果 | `assess_result_name` | **L2 (低敏感)** | 保持原样 |

## 3. 功能需求矩阵

### 3.1 数据生成需求 (F-1)
- **F-1.1**: 生成符合 GB 11643-1999 校验码的 18 位真彩校验身份证号。
- **F-1.2**: 生成包含恶性肿瘤/乙肝 (L4) 及 HIV/重度精神分裂症/亨廷顿舞蹈病 (L5) 的真实病史场景。
- **F-1.3**: 包含类似 `[DICOM-CT: /radiology/chest_ct_01.dcm]` 的真实图文病例路径。
- **F-1.4**: 命令行支持指定输出路径 (`--output`)、记录数量 (`--count`) 与随机种子 (`--seed`)。

### 3.2 算法 Pipeline 需求 (F-2)
- **F-2.1**: 对 27 个字段进行 3-Layer 分类分级 (L1~L5) 标注。
- **F-2.2**: 对 PII 字段自动进行格式感知脱敏 (ID_CARD, NAME, ADDRESS)。
- **F-2.3**: 对文本中的 L4/L5 敏感诊断自动执行强剥离与标准化替换。
- **F-2.4**: 输出结构同时包含分级报告与脱敏清洗数据，并**强约束 100% 绝对无 L4/L5 原始字符串泄露**。

### 3.3 全栈集成需求 (F-3)
- **F-3.1**: Agent 服务暴露 REST API `POST /v1/medical/process` 及 `POST /v1/pipeline/process_records`。
- **F-3.2**: Python 后端代理 `POST /api/medical_pipeline` 与 `POST /api/pipeline/process`。
- **F-3.3**: Go 后端代理 `POST /api/medical_pipeline` 与 `POST /api/pipeline/process`。
- **F-3.4**: Web 控制台提供 `MedicalPipelinePanel.tsx` 页面，支持一键从 `kangyang.csv` 加载数据并分栏展示结果。

---

## 4. 验收标准

1. **身份证校验格式**: `gen_id_card()` 生成的所有身份证号必须 100% 通过 GB 11643-1999 校验码计算。
2. **零 L4/L5 原始词汇泄露**: 治理后 `sanitized_data` 中包含的任意字段，绝不出现 `HIV`、`恶性肿瘤`、`精神分裂症` 等原始中英文敏词。
3. **测试覆盖率**: 单元测试 `tests/test_medical_pipeline.py` 与 `tests/test_pipeline.py` 全部 100% 通过。
4. **双后端可切换**: Web 控制台切换 Python REST 或 Go 后端（REST 代理通道）均能成功跑通。
